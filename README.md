# OpenMV 入门：颜色跟踪与手势识别

面向 OpenMV Cam H7 的学习项目。目标是识别握拳、张掌、剪刀手。

## 当前进度

- 已在用户设备上跑通红色色块跟踪和目标中心显示。
- 已整理画面翻转设置及中心偏差输出代码。
- 已准备手势图片采集脚本。
- 手势数据尚未采集，模型尚未训练或部署；当前代码还不能识别三种手势。

设备来自学习过程中的 IDE 截图：OpenMV Cam H7（STM32H743）、OV5640 摄像头，固件 4.6.20。
仓库代码是在对话中运行过的代码基础上整理的；整理后的文件尚未重新在板子上验证。
脚本使用 OpenMV MicroPython 的 `sensor` 模块，应在 OpenMV IDE 中连接摄像头运行。
普通电脑 Python 无法直接运行这些摄像头脚本。

## 文件

| 文件 | 用途 |
| --- | --- |
| `red_tracking.py` | 找到最大的红色色块，画框并输出位置与中心偏差 |
| `dataset_capture.py` | 提供不带绘图叠加的画面，配合 IDE 保存训练图片 |

## 运行颜色跟踪

1. 用 USB 数据线连接 OpenMV，在 IDE 中连接摄像头。
2. 打开 `red_tracking.py`，点击运行。
3. 前两秒保持场景和光照稳定，之后移动红色物体观察绿色方框。
4. 打开串行终端查看 `x`、`y`、`x_error`、`y_error`。

QVGA 画面为 320 × 240，以 `(160, 120)` 为中心参考。
横向偏差为负表示目标在画面左侧，为正表示在右侧；纵向为负表示在上方，为正表示在下方。
这两个偏差的单位是像素，不代表实际空间距离。
当前脚本在没有找到目标时不输出新的目标坐标。

实际调出的红色 LAB 阈值是 `(0, 100, 31, 127, -128, 127)`。
它只针对当时的目标和环境，不能保证换光照后仍然有效。
可以通过“工具 → 机器视觉 → 阈值编辑器”重新调整。

脚本在初始化时开启上下翻转和左右镜像，组合相当于旋转 180°。
按实际安装方向修改 `sensor.set_vflip()` 和 `sensor.set_hmirror()`。

## 下一步：采集手势图片

先以画面中只有一只手、手势朝向摄像头为入门场景，训练四分类模型：

| 类别名 | 内容 |
| --- | --- |
| `fist` | 握拳 |
| `palm` | 五指张开的手掌 |
| `victory` | 剪刀手 / V 字手势 |
| `none` | 无手的背景及其他非目标手势 |

### 建立数据集

1. 停止当前脚本。
2. 在 IDE 中选择“工具 → 数据集编辑器 → 新建数据集”。
3. 新建一个专用空文件夹，例如本项目下的 `datasets/gesture`，并选中它。
   **新建数据集可能清空所选文件夹，务必选择专用空文件夹。**
4. 使用“新建类别文件夹”（通常为 `Ctrl+Shift+N`）分别创建上述四个类别。
5. 打开并运行本项目的 `dataset_capture.py`，选择要采集的类别。
6. 使用“采集数据 / Capture Data”（通常为 `Ctrl+Shift+S`）保存图片。

先每类拍少量图片确认分类和保存位置正确，再逐步增加数据。
拍摄时变化手的位置、距离、角度与背景；不要连续保存大量几乎相同的画面。
保留部分独立拍摄的图片用于测试，避免相邻的重复画面同时出现在训练集和测试集。
如果希望识别多个人的手，需要采集多人的样本。
采集和后续推理应使用一致的翻转、裁剪和颜色预处理。

`datasets/` 和 `screenshots/` 已加入 `.gitignore`，个人采集图片默认留在本地。
不要用颜色跟踪脚本采集训练图片，以免把绿色方框和十字拍进数据集。

### 后续训练与部署计划

1. 将带类别的图片导入 Edge Impulse，训练小型图像分类模型。
2. 使用适合 H7 内存限制的输入尺寸和网络，并检查量化模型的 Flash / RAM 占用。
3. 导出模型、标签和配套推理脚本，再确认与设备固件 API 的兼容性。
4. 上板测试三个手势以及无手场景，实测速度、误识别和漏识别。

这里没有附带训练模型，也没有预设准确率或帧率。
完成以上步骤之后，再添加正式手势推理脚本。
